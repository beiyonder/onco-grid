# Work report — P5 C2 Trial profile

## Problem

The accepted library attached a five-tab detail panel to each result, but the panel did not yet implement the blueprint's dominant trial entity, source layer, complete India-site hierarchy, explicit unknown/conflict states, or close-and-return interaction. Source provenance, registry eligibility text, and activity competed as peer tabs. A pre-existing over-escaped date regular expression also replaced valid registry dates with the current date, causing displayed update dates and source-readiness ordering to be wrong.

## Decision

Deliver Phase 1 slice 2 on `feat/trial-profile`. Keep the profile attached to the search results, but reduce its primary sections to Overview and Sites & status. Present the registry as a visible blue source layer; preserve registry and independent site assertions as separate text-labelled surfaces; render unknown and conflict explanations explicitly; show every retained India site grouped by state and ordered by city; put eligibility text, provenance, and history behind accessible disclosure controls. Add Close profile, storing the originating result, page position, and mobile list scroll position; opening moves focus to the profile title and closing returns focus and position to the origin. Correct the date regular expressions at the source rather than masking incorrect output.

## Evidence

- Normal 285-record load — the selected result identifier and profile source identifier matched; the profile showed the brief title as the dominant heading, official registry title in Overview, registry identifier and secondary identifier, registry update date, snapshot date, sponsor, design, conditions, interventions, source link, and retrieval time.
- Date normalization — `2026-08-14` remains `2026-08-14` and month-only `2026-08` normalizes to `2026-08-01`; the selected registry record displayed 11 Sept 2026 with an age of eight days instead of incorrectly displaying the current date.
- Source/status hierarchy — registry declaration and independent site confirmation appeared as separate labelled regions. A real record displayed `Site confirmation remains unknown` with explanatory text that registry recruitment does not prove current site screening availability.
- Conflict path — the synthetic discrepancy fixture displayed `Registry and site sources conflict` as an alert, retained `Open to recruitment` as the registry assertion and `Site reports temporary pause` as the human assertion, and stated that neither overwrites the other.
- India sites — the Sites & status section rendered every retained site for the selected record, grouped by state and ordered by city, with registry site state and `Not independently confirmed` shown separately. Tested records rendered 8, 12, and 18 retained India sites and linked to the exact ClinicalTrials.gov record.
- Keyboard and return behavior — keyboard activation moved focus to `trial-profile-title`; switching to Sites & status retained focus on the selected tab; Close profile returned focus to the exact origin card, reset `aria-pressed=false`, restored the stored page position, and restored the mobile result-list scroll offset.
- Desktop at `1440×1000` and narrow mobile at `390×844` — no page-level horizontal overflow. Mobile flattened source-status regions and site rows to one column while retaining source/date labels and the close action.
- Reduced-motion emulation set transition duration to `0.00001s` and scroll behavior to `auto`.
- Final desktop open → Sites & status → close flow produced zero console warnings, console errors, or page errors.
- `node --check web/app.js`, `git diff --check`, `python3 research/validate_ledger.py` (70 records), and `python3 scripts/fetch_india_oncology_trials.py --validate-only` (285 records) passed.

## Risks and gaps

The dated snapshot contains registry-declared site state but no independent site-specific confirmation, so every real site correctly remains unconfirmed. The synthetic fixture demonstrates the conflict branch but is not evidence of prevalence. Trial room conversation, participant roles, follow persistence, and resolution states are intentionally deferred to the next slice. The profile remains browser-memory UI with no identity, persistence, backend, or production access boundary. P5 validation and product lock remain open.
