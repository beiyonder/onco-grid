# Work report — P5 C2 Trial library

## Problem

The accepted trial-first screen exposed functional search and an attached detail panel, but its hierarchy did not make the dated source, registry assertion, and separate human site-confirmation state easy to distinguish. Loading briefly rendered fallback fixtures, source failure existed only in the global bar, filters lacked visible labels, result selection replaced the focused element, and the future List/Map relationship was absent.

## Decision

Deliver Phase 1 slice 1 on `feat/trial-library` without changing the dataset or runtime. Make the result list source-first: keep a persistent result count and snapshot date, use visibly labelled compact filters, show each record's source/ID/update trace, state registry and site confirmation separately in text, and expose List with Map explicitly unavailable until location handling is validated. Add deterministic loading, empty, source-error, retry, and recovered states. Preserve keyboard focus and scroll position when selecting a result.

## Evidence

- Pull request `#3` merged the behavior-preserving source split; this branch started from updated `main` at `e0608ab`.
- Normal source load at `1440×1000` — 285 registry trials loaded; snapshot date displayed as 16 Sept 2026; the first result named ClinicalTrials.gov, NCT identifier, registry update date, registry declaration, and independent site-confirmation state; no horizontal overflow.
- Search and empty state — `Mumbai` returned 161 records with the existing 60-card rendering cap; `no-such-trial-zzq` produced a labelled zero-result state and no selected detail; Clear filters restored 285 records and returned focus to Search.
- Loading state — while the registry request was held, the list exposed `aria-busy=true`, three skeleton records, source-pending copy, and a disabled refresh action; after release it returned to 285 records with `aria-busy=false`.
- Source-error state — an aborted snapshot request produced a visible alert, four clearly labelled synthetic fallback records, a missing-snapshot label, and Retry source; retry recovered to 285 real registry records and removed the alert.
- Keyboard — activating the second result retained focus on the newly rendered selected card, preserved its viewport position, set `aria-pressed=true`, and retained the existing 3 px focus outline.
- Narrow viewport at `390×844` — labelled Search, Condition, Site confirmation, and India state controls flattened to one column; result/source context remained visible; no horizontal overflow (`scrollWidth = clientWidth = 390`).
- Reduced-motion emulation — animation and transition durations reduced to `0.00001s`; document scroll behavior became `auto`.
- Final browser reload, Mumbai search, reset, and selection flow — zero console warnings, console errors, or page errors.
- `node --check web/app.js`, `git diff --check`, `python3 research/validate_ledger.py` (70 records), and `python3 scripts/fetch_india_oncology_trials.py --validate-only` (285 records) passed.

## Risks and gaps

The list intentionally renders at most 60 cards and asks the user to narrow larger result sets; this has not been tested with oncology users. Map is visibly unavailable rather than approximating coordinates or site availability. The attached detail panel still uses the prior trial-profile structure; source/status hierarchy inside that profile, close/return behavior, and full focus restoration belong to the next slice. Source failure retains synthetic fixtures only when no real snapshot has loaded and labels them explicitly. P5 validation and product lock remain open.

Then implement Phase 1 slice 2: one dominant trial profile with registry source plane, all retained India sites, separate registry and site-confirmed assertions, explicit unknown/conflict states, and close/return behavior that preserves the originating result and focus.
