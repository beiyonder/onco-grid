1. Direction and decisions

INFERENCE · recommendation The product should be a trial pre-screening and coordination workspace, not a library followed by a long manual form. Its unit of work is a versioned patient–trial assessment; both entry directions open the same evidence and decisions.

Oncologist · patient first

Patient record → review available facts → run matching across a declared trial set.

PI / coordinator · trial first

Trial + cohort + site → approve criterion interpretation → screen a declared synthetic patient set.

One shared assessment
Machine finding + exact patient evidence + exact trial criterion → human review → resolve gaps → rerun → record a screening disposition → prepare an explicitly simulated handoff.

Five decisions that make the renovation coherent

  1. Keep the general library. Give patient matching a dedicated contextual workspace; do not quietly turn general search into patient-specific ranking.
  2. Separate evidence, inference, and authority. A source assertion, machine match, clinician review, and trial-team eligibility decision are different records.
  3. Automate before asking people to review. Retrieve candidates, evaluate supported criteria, link evidence, expose contradictions, and suggest gap work. Never manufacture absent facts.
  4. Make the PI a first-class workflow owner. Study/cohort/site scope, protocol version, candidate queue, screening assignment, and disposition need an explicit home.
  5. Make geography and subject independent lenses. India/global × trials/drugs/topics × list/spatial; one declared result set and consistent context.

Suggested reading: 60 seconds: this section and authority. Ten minutes: audit, journeys, matching, delivery. Deep dive: data contracts, acceptance matrix, and release gates.

Pushback on one product claim: “Highest match score” is not “best trial,” treatment benefit, or probability of eligibility. The plan includes scoring, ranking, close-match policy, and eligibility workflow, but requires their meanings and clinical authority to be explicit. A disclaimer alone does not make clinical matching non-clinical.

The viewer must open the original artifact, not a reconstructed fact card labelled as an original. Show document title/type, synthetic watermark, authored/observed/imported dates, origin, content version and linked facts. Select a fact to open its exact section/span or structured JSON path. If an original is absent or unreadable, say so.

Desktop: document list and selected viewer. Mobile: one viewer with a Back to sources action. Offer “View original” and synthetic-only download; never execute embedded document scripts or remote resources. Keep original content immutable; corrections create new assertions/revisions. Retain raw wording alongside normalized values and conversion explanations.

A gap is a resolvable workflow, not a yellow badge

Detected → proposed task → accepted/assigned → evidence received → reviewed → reassessed
                                    ↘ unable to obtain / cancelled (reason retained)
Evidence received ≠ fact confirmed ≠ criterion satisfied ≠ eligibility determined
  • Each gap names the required concept, affected patient–trial–cohort criteria, existing sources inspected, owner and next action. Do not turn a missing report into advice to order a test or change treatment.
  • “Provide evidence” opens the synthetic source chooser or structured synthetic manual-entry form pre-scoped to the missing concept. It cannot auto-fill a positive result.
  • A coordinator may attach evidence; only the permitted demo reviewer confirms a clinical assertion. A conflict displays both sources and requires an explicit choice/reason or remains unresolved.
  • Use stable task IDs and explicit links. Deduplicate equivalent retrieval work by patient + information need + time window; link all affected pair criteria. Never deduplicate by criterion number alone.
  • After confirmation, compute impacted assessments from fact dependencies. Mark old runs stale; create a new run rather than mutating the old one. A resolved task can still yield an unsatisfied criterion.
  • Inbox offers “Open and resolve” for evidence-bearing tasks, not a generic checkbox that implies the evidence exists. “Unable to obtain” closes operational effort while the assessment remains indeterminate.
Success trace and failure/recovery trace

Success: Patient 2 has a missing biomarker assertion → an assessment exposes Unknown with a source need → coordinator accepts retrieval → opens the bundled synthetic molecular report → reviewer confirms the assertion → new record version → affected pair reruns → machine finding changes with source link → clinician records their review.

Failure: two reports disagree → neither latest-date nor source type automatically wins → result is Conflict → reviewer records the reconciliation or cannot resolve it → new assessment is generated only from accepted inputs; earlier signed review remains historical and cannot approve the new version.

7. Matching specification

INFERENCE · proposed clinical-capability contract Matching must be a reproducible pipeline, not a single opaque AI answer. Bidirectionality changes the iteration axis, never the pair evaluator.

Pipeline and decision logic

  1. Freeze inputs. Patient fact/source versions; trial registry content hash; reviewed criterion/cohort model version; evaluation date; explicit scope and filters; engine and scoring policy version.
  2. Retrieve candidates with recall in mind. Use explicit recorded condition concepts and reviewed aliases; preserve broad/basket-trial possibilities. Unknown biomarkers or incomplete history must not silently eliminate candidates. Show every hard retrieval filter and exclusion count. Compare retrieval separately against clinician-labelled candidate sets.
  3. Acquire full eligibility source. Fetch complete retained text when available; distinguish registry summary from full protocol. Truncated, missing, ambiguous or unreviewed interpretation is an assessability limitation, not permission to guess.
  4. Structure protocol logic. Preserve inclusion/exclusion sections, AND/OR/NOT, exceptions, cohort/arm applicability, threshold operators, units and timing anchors. Link every expression to exact source spans. Human review publishes a criterion model; a machine draft is not authoritative.
  5. Normalize patient assertions. Concepts, typed values, units, assay/specimen context, observation time and negation. Maintain source values. Do not infer stage, progression, line of therapy or test results from hints.
  6. Evaluate a pair. Return criterion findings with cited assertions, predicate trace, time/unit checks, missing inputs and abstention reason. No unsupported medical equivalence or conversion.
  7. Aggregate transparently. Distinguish evidence-supported criteria, violations, unknowns, conflicting evidence, unsupported rules and out-of-scope conditions. Derive ranking only from the declared policy.
  8. Review, correct and rerun. Human review is an overlay referencing immutable machine findings. An override needs author/reason/evidence; it does not rewrite the algorithm’s output.

Criterion evaluation algebra

Use predicate truth true | false | unknown, plus explicit reason flags for missing, stale, conflicting, ambiguous and unsupported inputs. For AND: false if any child is false, true only if all are true, otherwise unknown. For OR: true if any child is true, false only if all are false, otherwise unknown. NOT preserves unknown. Retain the child trace even where one branch decides the root.

An inclusion root is satisfied when its predicate is true. An exclusion root is satisfied when its prohibited predicate is false. Never invert an unknown exclusion into a pass. “Not applicable” requires an explicit evaluated branch/applicability rule, not a reviewer shortcut to improve a score. A score counts applicable top-level requirements, not every parsed leaf, so splitting a sentence cannot inflate it.

Supported operators: exact reviewed concept match, membership, numeric range with explicit comparators, reviewed unit conversion, dated interval and recorded sequence, AND/OR/NOT and explicit branch applicability. Unsupported expressions stay visible. Date precision, timezone and inclusive/exclusive boundaries are part of the predicate; partial dates produce unknown whenever a boundary cannot be resolved.

Execution, capacity and failure behavior

Pure interface: evaluatePair(patientVersion, criterionModelVersion, evaluationContext) → PairAssessment. Run interfaces enumerate candidates then call the same function. Parse/version each trial model once; index assertions by concept; avoid a full-source scan per criterion. With 12 synthetic patients × 285 current India records, the upper pair count is 3,420; predicate work is approximately pair count × applicable predicate nodes. That is a sizing bound, not a performance result, and only modelled records are evaluable.

Start local and synchronous for small batches with cooperative chunking/progress/cancellation; add a Web Worker only if measured UI blocking justifies it. Proposed responsiveness target: interactions remain responsive with no evaluator task monopolising the main thread for over 50ms; record measurement hardware and corpus. Larger institutional cohorts are outside this demo capacity claim.

Global read requests use existing bounded APIs. Preserve allowlisted parameters, upstream timeout and contact stripping; add complete criterion retrieval only through a reviewed public-source contract. Cancel/ignore superseded requests; cache public records by ID/version in session, never assume a cached summary is complete. Page failure retains loaded records and marks the run partial; retry is explicit. No automatic external side effects occur.

Browser memory remains the workflow store: reload resets synthetic edits and audit history. Bundle baseline fixtures and offer Reset demo with confirmation for unsaved work. No durable audit, backup/RPO, multi-user consistency or production security claim is made. Those need a separate architecture if real deployment requirements arrive.

Clinical and usability evaluation

  • Before algorithm tuning, have independent clinician/research reviewers label candidate inclusion, criterion truth, evidence spans, uncertainty and exclusion reasons across the frozen corpus. Adjudicate disagreements and preserve the original labels.
  • Report retrieval recall separately from criterion accuracy, false exclusions, false supported findings, abstention rate, citation correctness and protocol coverage. Report denominators and stratify by disease/model type; a high average cannot hide a critical exclusion error.
  • Require zero known critical false passes and complete evidence traceability in the release corpus. This is a finite-corpus gate, not proof of clinical safety. Numeric clinical-performance thresholds and validation sample size remain owner/clinical-lead decisions before real use.
  • Run observed synthetic tasks with an oncologist, PI and coordinator. Proposed operational goals: lower time to a defensible review shortlist, fewer manual criterion/source actions, and no lost context. Establish the baseline first; compare success, time, corrections and reviewer trust without retaining participant identity.
  • Measure rank utility against a clinician-authored review shortlist, not enrolment outcomes or claimed treatment benefit. Examine whether unknown-heavy cases are unfairly buried.

The machine findings for one patient version × trial/cohort model version × evaluator policy and date.

Stale
A result whose input version has changed; retained for history but no longer current.

Review prompt: a gap task is resolved. Can the patient become eligible automatically?

No. The task resolution may mean evidence acquired or unobtainable. Evidence must be reviewed; changed inputs generate a new assessment; clinical eligibility remains a separate authorised human decision.

Only the geography of the loaded/filtered set, with declared placement precision. They cannot represent all 500 records, current site availability or patient access.

Compare patient version, trial/cohort model, evaluation time and engine/policy versions first. Equal inputs must produce identical pair findings; differing candidate sets may change rank, never criterion truth.
